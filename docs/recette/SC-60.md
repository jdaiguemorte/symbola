# Rejeu SC-60 — Le dîner au château (proposé, lot 60)

Scénario **proposé** par le lot 60 : le cahier des charges n'en a pas (fonction hors cahier des
charges, ADR 0099). À valider par Julien avant de rejoindre la liste des scénarios.

## Le scénario

Personas du jeu fictif (`symbola-synthetic-users.json`) : **Camille** (SU-01, wedding planner) et
**Karim** (traiteur, Karim Haddad). Le lieu est fictif : le « Château des Essais ».

| Étape | Attendu |
| --- | --- |
| 1. Camille note le lieu une fois | Sur la fiche du lieu, « Plans de salle » : la salle des fêtes (20 × 12 m), son fond de plan (capture du PDF du lieu, PNG) calibré par deux points, ses installations (une prise de deux prises 16 A près de la scène, l'accès de livraison, les issues). |
| 2. Elle prépare « Dîner 120 en rondes » | Douze rondes de 10, la table d'honneur, le buffet, le DJ, la piste ; à la souris, puis au clavier seul pour une table (Tab, flèches, R) ; capacité calculée ; un chevauchement signalé, corrigé. |
| 3. Elle copie la configuration dans le mariage | Le plan de l'évènement part de la configuration ; le lieu n'est pas modifié. Le buffet désigne Karim (retenu), relié à la prise ; le DJ aussi : la prise est signalée surchargée (3 prises demandées pour 2), Camille relie le DJ à une autre prise. |
| 4. Elle diffuse le plan | Version 1 ; le client, à qui la rubrique « Plan de salle » est ouverte, le lit en lecture. |
| 5. Karim ouvre son lien | Il voit la nouvelle version signalée, son emplacement en évidence, ses besoins et sa prise, l'accès de livraison et les issues ; les autres prestataires par leur type seulement ; aucune note interne ; il imprime le PDF à l'échelle. |
| 6. Les tables passent au plan de table | « Créer les tables du plan de table » : les treize tables arrivent une fois dans le plan de table du dîner ; le placement des invités reste au lot 50. |
